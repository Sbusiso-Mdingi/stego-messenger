# Benchmark results

Generated by `python -m src.benchmark`. The sweep embeds random payloads (which are
statistically indistinguishable from the AES-GCM ciphertext the toolkit actually hides)
into a fixed corpus of public-domain images, at a range of payload sizes, repeated over
five seeds, for both embedding methods:

- **sequential**: LSB replacement in raster order (the v0.3 baseline);
- **keyed**: LSB matching (a random +1 or -1 change) at key-seeded scattered positions
  (new in v0.4, and the default for `src.package.seal`).

It records distortion (PSNR, SSIM), exact-recovery rate on the lossless PNG carrier, and
three detectors: chi-square and RS analysis, which target LSB replacement, and the
calibrated HCF centre of mass (HCF-COM), which targets LSB matching.

Numbers below are from `latest/benchmark.json`: two methods x five images
(astronaut, coffee, rocket, chelsea, hubble_deep_field) x six payload sizes x five seeds =
300 embeddings. Confidence intervals are the 95% normal-approximation interval over the
25 observations at each point. The exact environment (library versions, platform, git
commit) is recorded in the JSON.

The HCF-COM shift is the stego image's calibrated ratio minus that of its own cover, so it
uses information a real steganalyst would not have. Its raw ratio on clean covers ranges
from 0.71 (chelsea) to 0.98 (astronaut), wider than any shift above.

## Distortion and recovery

Both methods change the same number of values by the same amount, so distortion matches:
PSNR is 64.2, 61.1, 57.2, 54.2 and 51.6 dB at 5, 10, 25, 50 and 90% (SSIM 0.9998 to
0.9960), and every embedded payload is recovered bit-for-bit from the PNG.

## What this shows

**Sequential replacement is visually invisible but statistically obvious.** At a 10%
payload the stego image is 61 dB from its cover with an SSIM of 0.9996, yet RS analysis
recovers the embedding rate as 0.12, cleanly separated from the clean control at 0.03.

**Keyed matching removes most of the signal RS and chi-square rely on.** Matching does not
create the pairs-of-values symmetry those detectors measure, and scattering the changes
removes the "embedded top, clean bottom" contrast that sequential embedding leaves. At 10%
the keyed RS reading (0.034) sits inside the clean control's interval; even at 90% it is
0.068, against 0.834 for sequential.

**It is not uniform across images.** On astronaut, whose black background has many
channel values at 0, RS still rises with keyed embedding (0.067 at 10%, 0.128 at 25%,
against 0.096 and 0.179 for sequential). At a value of 0 the only legal change is +1, which
is exactly an LSB flip, so saturated regions behave like replacement. On coffee, rocket and
chelsea the keyed RS reading does not move from the clean level.

**A detector built for matching sees what RS misses, at larger payloads.** HCF-COM moves
steadily with keyed embedding, from -0.016 at 10% to -0.148 at 90%, with tight intervals.
At small payloads it responds less to keyed than to sequential embedding; from 50% upward
it responds more. Its image-to-image spread means it cannot flag a single image without the
cover at these payload sizes, but stronger matching detectors and learned classifiers exist.
The toolkit's claim is therefore narrow: keyed matching defeats the two classical
replacement detectors, it does not make the payload undetectable.

**Recovery is exact only on the lossless carrier.** The transformation experiments in
`src/attacks.py` and `evaluate_attacks` show that JPEG, noise, cropping and resizing
destroy the LSB plane for both methods.

## Reproducing

```bash
pip install -e '.[dev]'
python -m src.benchmark --out docs/benchmarks/latest
```

The corpus images are regenerated from scikit-image's bundled public-domain samples, so
they are not committed; only the result files are. Pass `--methods`, `--seeds`,
`--fractions` and `--images` to change the sweep.
