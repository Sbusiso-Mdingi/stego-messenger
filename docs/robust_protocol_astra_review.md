# Astra review of the robust protocol draft (23 November 2026)

1. **The test is not fully insulated from development.** “Never on test covers” explicitly constrains real round trips, but not simulations. Nor are the implementation and decoder frozen alongside the parameters. **Fix:** prohibit test covers and near-duplicates in all development; freeze code, dependencies, parameters and decoder options before test access. Permit no tuning from either channel’s test results.

2. **The development selection rule is not operationally defined.** Candidate ranges, simulated trial counts and the denominator for “99%” are unspecified. Repeating easy simulations could inflate success. “At most 10” real trips permits very little validation, and a send using one parameter set does not validate another. **Fix:** specify a finite candidate grid and common simulation suite; select one candidate, then require ten real confirmation trips. Predeclare what happens if confirmation fails.

3. **19/20 does not establish 95% reliability.** Even assuming independent, representative covers, 19 successes gives an exact two-sided 95% confidence interval of approximately **75%–99.9%**. **Fix:** either call this a feasibility pilot and report uncertainty, or choose the sample size and acceptance threshold from a stated minimum reliability and confidence requirement.

4. **Cover selection permits an easy, unrepresentative test.** Twenty hand-picked Commons or personal photographs could favour textured, large-capacity images. Hash differences do not establish different underlying content; the development set already contains repeated content. **Fix:** draw the holdout independently from a predefined pool, exclude related images, and prespecify representation of smooth/textured scenes, aspect ratios and resulting pixel counts.

5. **A pass can conceal unacceptable image damage or redundancy.** There is no quality bound, while a small payload may survive through excessive redundancy. Smallest `k` is not necessarily least distortion: coefficient quantisation steps, `Z` and the number of embedded bits also matter. **Fix:** set an acceptable image-quality budget and report useful plaintext capacity and coding overhead; otherwise explicitly label the outcome *recovery-only*, not evidence of practical steganographic quality.

6. **The retry rule allows eventual-pass selection.** New parameters and new covers protect each holdout, but repeated attempts until one passes can still produce a misleading headline. **Fix:** predeclare the maximum number of confirmatory attempts, retain every attempt in the main report, and account for repeated testing if making an overall statistical reliability claim.

7. **The channel evidence does not fully characterize the actual JPEG-input pipeline.** Measurements used PNGs; stego inputs will be JPEGs. Matching quantisation tables does not establish identical processing, and iPhone repeatability was not measured. **Fix:** pilot actual pre-shaped and stego JPEGs, including repeated identical sends; record device, iOS, WhatsApp version and the complete import/save route. Limit conclusions to that configuration. “Harsher” settings do not guarantee that another encoder is easier.

8. **The recovery boundary and framing coverage are unclear.** Known seeded messages and one fixed blob length could let expected plaintext or length inadvertently assist decoding. The test would not demonstrate general header or variable-length handling. Also, 140 UTF-8 bytes need not mean 140 characters. **Fix:** isolate recovery to the received image, credentials and frozen configuration; compare expected bytes only afterward. Add separate framing tests across lengths and state the claim in bytes.

9. **Important method choices remain unfixed beyond `Z`, `k` and `m`.** Header repetition, interleaving, RS shortening/padding, QIM tie handling and decoder fallback rules can materially change success. Capacity accounting is consequently ambiguous. **Fix:** freeze these choices before confirmation, verify the asserted blob size, and calculate capacity after all framing and error-correction overhead—not from raw coefficient slots.

10. **The descriptive metrics lack reproducible definitions.** BER could exclude synchronization failures or failed decodes, making it optimistic. PSNR/SSIM against an original with different dimensions are undefined without alignment. **Fix:** define BER denominators, header errors and treatment of unreadable cases; specify image alignment, colour space and metric settings. Report every cover, including failures, rather than successful recoveries alone.
